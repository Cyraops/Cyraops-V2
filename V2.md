# Cyraops V2

A local-first Cyraops: the same CRM interface, with the DeepSeek Harness doing the
work underneath instead of a hand-rolled agent loop.

Base: production branch of the V1 repository at `99df4ba` (verbatim copy — V1 is
untouched and remains the shipped product).

## Shape

```
Cyraops V2 = CRM interface (ours, unchanged)  +  DeepSeek Harness engine
```

The UI stays exactly as it is. What changes is what sits behind it:

| Today (V1) | V2 |
| --- | --- |
| Custom agent loop, 53 hand-written tools | Harness runtime: tools, plugins, skills, sessions |
| Server-side browser (was a paid VM) | Local capability agent on the user's machine |
| Approvals coded into the assistant route | Harness approvals + policy, surfaced in our UI |

## Why the harness

`@deepseek-ai/dsh` is MIT licensed. It already provides what V1 rebuilds by hand:
a plugin system, tool registry, session/context management, subagents, skills and
a policy layer. Using it as a library — not as the UI — means our CRM inherits
those capabilities as they improve upstream.

## Ground rules

1. **V1 stays untouched.** This directory is a copy; no commits go back.
2. **One UI.** No DeepSeek interface is ever shown; the harness is headless here.
3. **Local-first.** Work runs on the user's machine when it can (their sessions,
   their files), and only bursts into the cloud for unattended or heavy jobs.
4. **Capability is per-capability.** Browser, files, screen and shell are granted
   separately, each visible and revocable.
